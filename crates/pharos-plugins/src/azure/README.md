# azure

[CoreDNS v1.15.0 README](https://github.com/coredns/coredns/blob/v1.15.0/plugin/azure/README.md)

## azure

- Syntax matches CoreDNS v1.15.0: `azure RESOURCE_GROUP:ZONE... { tenant ID; client ID; secret SECRET; subscription ID; environment ENV; fallthrough [ZONE...]; access public|private; refresh DURATION }`. The issue text names the properties `client_id` and `client_secret` and writes the argument as `ZONE:RESOURCE_GROUP:HOSTED_ZONE`; v1.15.0 is the baseline, so the properties are `client` and `secret` and the argument is `RESOURCE_GROUP:ZONE`, split on the first `:`. A missing `:`, an empty resource group or zone, and a repeated `RESOURCE_GROUP:ZONE` are Corefile errors. A bare `azure` is valid and serves nothing. Every `azure` line of a Server Block joins one handler (as `parse` loops over `c.Next()` in CoreDNS); `access` applies only to the zones of its own line.
- `refresh` takes a bare integer as seconds or a Go duration (`3m`, `1h30m`, `500ms`) and must be positive; the default is one minute. `environment` takes `AZUREPUBLICCLOUD`, `AZUREUSGOVERNMENTCLOUD`, `AZURECHINACLOUD` or `AZUREGERMANCLOUD` (and go-autorest's aliases `AZURECLOUD` and `AZUREUSGOVERNMENT`), compared in upper case, and selects the Resource Manager and Active Directory endpoints. `AZURESTACKCLOUD` is rejected: go-autorest would read its endpoints from a file named by an environment variable.
- Nothing is fetched at setup or when the Plugin is built. The Startup hook (and RestartFailed) starts one background task and returns at once; Restart and Shutdown abort the task, including a request in flight, and wait for it to end. The task syncs every hosted zone immediately, then waits `refresh` after each sync finishes, as CoreDNS's `run` does. A Query never waits on Azure and never takes a lock the sync holds: each hosted zone has an atomically swapped `ZoneHolder`, and a refresh publishes a fully built Zone in one store.
- A hosted zone that has never loaded answers SERVFAIL, or falls through when `fallthrough` names the Query's zone. A failed refresh keeps the last good Zone and logs `Failed to update zones [NAMES]: errors updating zones: [...]`; the other hosted zones are still updated. All pages must succeed and the listing must hold an SOA at the apex (otherwise the update fails with `zone has no SOA record`), or nothing is published. One hosted zone's whole listing (every page, every retry, the token request) shares a one minute deadline, as in CoreDNS.
- REST calls follow the Go SDK v68 the CoreDNS release uses. Public: `GET {ResourceManagerEndpoint}/subscriptions/{subscription}/resourceGroups/{rg}/providers/Microsoft.Network/dnsZones/{zone}/recordsets?api-version=2018-05-01`. Private: `.../providers/Microsoft.Network/privateDnsZones/{zone}/ALL?api-version=2018-09-01`. Path parameters are percent-encoded. Every request carries `Authorization: Bearer TOKEN`. Pages follow `nextLink`; an empty page with a `nextLink` is followed; a `nextLink` that is not an absolute `http(s)` URL, that points to another scheme, host or port than Resource Manager (the bearer token must not leave it), or that repeats an earlier page ends the listing with an error. A listing larger than 256 MiB, or one response over 32 MiB, is an error. Redirects are not followed. A connection is opened for each request (syncs are at least a second apart); TLS uses the shared `pharos_server::tls` configuration with the system roots, built on the first `https` request.
- Authentication follows go-autorest `GetAuthorizer`. A non-empty `secret` selects client credentials: `POST {ActiveDirectoryEndpoint}{tenant}/oauth2/token?api-version=1.0` with the form `client_id`, `client_secret`, `grant_type=client_credentials` and `resource={ResourceManagerEndpoint}`. Otherwise the Plugin uses a managed identity (MSI) as adal does: with `MSI_ENDPOINT` and `MSI_SECRET` in the environment, App Service (`GET`, `api-version=2017-09-01`, `clientid`, header `secret`); with `MSI_ENDPOINT` alone, Cloud Shell (`POST` form, header `Metadata: true`); with neither, IMDS (`GET http://169.254.169.254/metadata/identity/oauth2/token?api-version=2018-02-01&client_id=...&resource=...`, header `Metadata: true`). `client` is the user-assigned identity's client ID when MSI is used. The environment is read when the Plugin is built.
- The token is cached and fetched again when it expires within five minutes (adal `defaultRefresh`), before the request that needs it, so a long listing never uses a stale token. `expires_on` (epoch seconds, number or string) wins over `expires_in` (string or number), as in adal; a token with neither is used once. Only the sync task asks for tokens.
- Retries follow autorest's defaults: after the first attempt, a request is retried up to 3 times on a transport error or status 408, 429, 500, 502, 503 or 504, with a delay of 30 s, 60 s, 120 s, or the `Retry-After` header in seconds when it is positive. Every wait is bounded by the one minute deadline of the hosted zone, so in practice a failing zone is attempted a few times. Other statuses (401, 403, 404, ...) fail at once. Token requests are not retried (adal retries IMDS itself; here the next sync does it).
- Record sets become Zone records as CoreDNS does: `A`, `AAAA`, `MX`, `PTR`, `SRV`, `TXT`, `CNAME` and `SOA`, plus `NS` for public zones only. Other types (`CAA`, ...) are ignored. A `TXT` record set's `value` list is one TXT record with those strings. The public API (`TTL`, `ARecords`, `SOARecord`, `minimumTTL`) and the private API (`ttl`, `aRecords`, `soaRecord`, `minimumTtl`) spell keys differently and Go matches them without case, so Pharos does too.
- Conversion is strict where CoreDNS panics or builds a broken record: a missing field, a bad IP address, a name that does not parse, a number outside its field (a TTL or SOA field over 32 bits, a port, preference, priority or weight over 16 bits), a TXT string over 255 octets or an empty TXT list fails the whole update, so the last good Zone is kept. Names are made absolute (`dns.Fqdn`) everywhere, which CoreDNS skips for the public API's SOA host and NS names.
- Several hosted zones may share one zone name (different resource groups, or public and private). CoreDNS looks the name up in each in order and stops at the first with an answer or NODATA. Pharos serves from one Zone, because a Zone writes the whole Response: the first loaded hosted zone in which the name exists answers, else the last loaded one (so its NXDOMAIN stands), else SERVFAIL or `fallthrough`. A name that exists in two hosted zones therefore never merges RRsets across them; CoreDNS does not merge them either.
- Private DNS zones have no NS records, but a Zone needs an apex NS RRset (RFC 2181 §6.1). When Azure lists none, the Plugin adds one NS record at the apex naming the SOA's MNAME (TTL of the SOA). It is visible only to a Query for the apex NS.
- Secrets: the client secret and access tokens are never written to a log, an error or `Debug` output (`Secret` prints `<redacted>`). A token endpoint error carries only the status, because an error page may echo the form with the secret percent-encoded. A Resource Manager error carries the status and the first 512 bytes of the response body, control characters replaced; any occurrence of the secret or the cached token in the error text is replaced by `<redacted>`.
- Not supported: client certificate and username/password authentication (go-autorest reads them only from `EnvironmentSettings` values that the Corefile cannot set in v1.15.0, so CoreDNS cannot use them either), Azure Stack, and HTTP-date `Retry-After` values (ignored, the backoff applies).
- Deviations from CoreDNS: IMDS is not probed at setup (CoreDNS fails setup with `MSI not available`); Pharos starts, serves SERVFAIL, and logs the token error on each sync. A hosted zone with no records beyond the SOA is served as an empty Zone. Per-Query work is the shared Zone lookup, which allocates nothing once warm for the cases `tests/allocations/azure_allocations.rs` covers (direct answers, in-Zone CNAME to a local target, NODATA, NXDOMAIN). The shared Zone Self Lookup paths (a CNAME or DNAME target without a Zone-tree record, NS Queries, apex SOA Queries; see the `file` Plugin) allocate until issue #86.
- No differential scenario exists: there is no Azure to run CoreDNS against, and the tests replace Resource Manager, Active Directory and the MSI endpoints with local HTTP stubs (`stub.rs`, `sync_tests.rs`; these port CoreDNS's `setup_test.go`, `azure_test.go` and `sync_test.go` and check the exact request paths, `api-version`s and headers).
- Deferred: a functional test through a started Server (the Corefile cannot point the Plugin at a stub), client certificate authentication, and consolidating the HTTP client, token source and sync loop (`http.rs`, `auth.rs`, `sync.rs`) with the `route53` and `clouddns` Plugins once those land (DRY follow-up).
